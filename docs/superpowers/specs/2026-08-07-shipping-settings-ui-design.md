# 送料設定画面のUI変更(削除ボタン・追加ポップアップ)設計書

作成日: 2026-08-07 / ステータス: 設計承認済み・実装未着手

## 1. 目的

送料設定画面の見た目と操作を、ユーザー提示のモックに合わせる。現在は削除がスワイプのみで発見しづらく、追加行に名前・金額の入力欄がそのまま並んでいて窮屈。

- 行ごとにゴミ箱アイコンを置き、削除を見えるようにする
- 追加は「+ 追加」の1行に集約し、入力はポップアップで行う
- 入力が不正なときは、該当する入力欄の直下に赤文字で理由を出す

## 2. 画面構成

### 2.1 プリセットの行

左から順に配置する。

| 位置 | 要素 | 挙動 |
|---|---|---|
| 左端 | 選択アイコン(未選択=白丸 / 選択中=青チェック) | — |
| 中央 | 名前 | ここをタップで**選択**を切り替える |
| 右 | 金額の入力欄 + 「円」 | タップで**その場で編集**。`TextField`と`Text("円")`を隙間なく並べ「100円」の見た目にする |
| 右端 | ゴミ箱アイコン | タップで**即削除**(確認ダイアログは出さない) |

- 削除に確認を挟まないのは、誤タップしても再登録が容易で、確認のたびに手数が増えるほうが煩わしいため。
- スワイプ削除(`.onDelete`)も併存させる。iOSの操作感として自然で、追加コストが無い。
- 選択中のプリセットを削除したら未選択(0円)に戻す。既存の挙動を維持する。

**実装上の注意:** `List`(`Form`)の行に`Button`を置くと、行のどこをタップしてもボタンが反応してしまう。ゴミ箱には`.buttonStyle(.borderless)`を付け、アイコン部分だけが反応するようにする。これを忘れると名前タップの「選択」が動かなくなる。

### 2.2 「+ 追加」行

プリセット一覧の末尾に置く。プラスアイコンと「追加」のラベルのみ。タップで追加ポップアップを開く。

現在の「名前欄 + 金額欄 + ⊕ボタン」が横並びになった行は廃止する。

### 2.3 追加ポップアップ

「+ 追加」で画面中央に出る小さな入力カード(背景は暗くする)。見た目はシステムのアラートに寄せる。

```
配送料を追加

名前   [                    ]
⚠️ 同じ名前が既に登録されています

金額   [              ] 円
⚠️ 金額が入力されていません

[キャンセル]              [OK]
```

- タイトルはセクション名に応じて「配送料を追加」「発送費用を追加」とする。
- ボタンは下部に「キャンセル」「OK」を横並びで置く。
- 赤文字は**該当する入力欄の直下**に出す。名前のエラーは名前欄の下、金額のエラーは金額欄の下。両方不正なら両方同時に出す。
- 「OK」ボタンは**常に押せる状態**にする。グレーアウトさせると押せない理由が分からないため、押させて理由を出す。

**なぜシステムのアラートではなく自前のポップアップか:** システムのアラートは本文を赤文字にできず、ボタンを押すと必ず閉じてしまうため、「不正なら閉じずに赤文字で理由を出す」という要件を満たせない。見た目をアラートに寄せた自前のカードを重ねることで、見た目と要件の両方を満たす。静的なビューを重ねるだけなので描画コストは掛からない。

**実装上の注意:** 重ねる先は`Section`や行ではなく`Form`自体(`.overlay`)にすること。`List`の行から提示するとSwiftUIが提示先を解決できず、タップしても何も起きない。背景をタップしても閉じない(誤タップで入力中の内容が消えるのを防ぐ)。

### 2.4 検証ルールとメッセージ

「OK」を押した時点で両方の欄を検証し、該当するメッセージをすべて表示する。1つでもエラーがあればポップアップは閉じない。

| 対象 | 条件 | メッセージ |
|---|---|---|
| 名前 | 空、または前後の空白を除くと空 | 名前が入力されていません |
| 名前 | 同じセクションに同名が既に登録済み | 同じ名前が既に登録されています |
| 金額 | 未入力 | 金額が入力されていません |

- 名前が空と重複の両方に当たることは無い(空なら重複判定はしない)。表示するメッセージは名前につき1つ。
- 金額が`0`は**エラーにしない**。送料無料の運用がありうるため。
- 入力欄を編集し直したら、その欄のメッセージを消す。直したのに赤文字が残っていると直っていないように見えるため。
- すべて妥当なら登録してポップアップを閉じる。

### 2.5 追加後の選択

未選択(または1件も無い状態)で追加したら、そのプリセットを自動で選択する。既に選択済みなら選択を移さない。既存の挙動を維持する。

## 3. 変更しない範囲

- `ShippingPreset`(データモデル)と`SettingsStore`(プリセット一覧・選択中ID・computed な既定値・移行処理)
- 配送料・発送費用の2セクション構成と、それぞれの補足文
- `PurchaseFormView`(仕入れフォーム側の表示・計算)
- サーバー側(変更なし。デプロイ不要)

変更するのは `ios/BarcodeSedori/Sources/Views/ShippingSettingsView.swift` のみ。

## 4. 検証

iOSにテストターゲットが無いため、ビルド成功と手動確認で検証する。

**ビルド**

```bash
xcodebuild -project "ios/BarcodeSedori/BarcodeSedori.xcodeproj" -scheme BarcodeSedori \
  -destination 'platform=iOS Simulator,name=iPhone SE (3rd generation)' \
  -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

**手動確認項目**

1. 行にゴミ箱アイコンが出て、タップで確認なしに削除される
2. ゴミ箱をタップしても選択が切り替わらない(名前タップだけが選択を切り替える)
3. スワイプ削除も従来どおり動く
4. 選択中のものを削除すると未選択になる
5. 「+ 追加」でポップアップが開き、名前と金額を入れて「追加」すると一覧に増える
6. 名前を空のまま「追加」→ 名前欄の下に「名前が入力されていません」が赤字で出て、ポップアップは閉じない
7. 既存と同じ名前で「追加」→ 名前欄の下に「同じ名前が既に登録されています」が出る
8. 金額を空のまま「追加」→ 金額欄の下に「金額が入力されていません」が出る
9. 名前も金額も空で「追加」→ 両方の欄の下に同時に出る
10. 赤字が出た状態で入力欄を直すと、その欄の赤字が消える
11. 金額に`0`を入れて「追加」→ エラーにならず登録できる
12. 未選択の状態で追加すると自動で選択される。選択済みなら選択は移らない
13. 配送料・発送費用の両セクションで1〜12が同じように動く
